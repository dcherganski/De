# Лична платформа за криптотърговия (PAPER по подразбиране)

Живи цени от Bybit и новини. TypeSafe Jev оценява вероятността за движение в следващите 30 минути, а
отделен риск-модул решава дали да има сделка. Сделките се **симулират** по живите котировки. Таблото е
на български.

> **Реална търговия няма в тази версия.**
> - LIVE се отказва на три места: в двигателя, в API-то и в таблото.
> - Поръчките през Bybit са заключени в адаптера.
> - Реални сделки се включват само с твое изрично разрешение и малък тест край до край.
>
> Jev не вижда бъдещето. Нищо тук не обещава печалба.

## Какво има вътре

| Част | Какво прави |
|---|---|
| `engine` | Отделен процес: пазарни данни (Bybit, резерва Kraken), 5-минутни свещи, новини (RSS), Jev, риск, изпълнение (PAPER), одит |
| `api` | FastAPI: вход със сесия, данни за таблото, контроли, криптирани ключове. Не говори с борси, освен при проверка на ключ. |
| `web` | Next.js табло; браузърът говори само с него, а то с API-то (same-origin) |
| `db` | PostgreSQL 16; одитът е само за добавяне (тригер в базата) |
| `mcp` | По избор, само за четене: портфейл, статус, сигнали, сделки, калибрация |

Проверените интеграции, с източници и дати, са в [`docs/integrations.md`](docs/integrations.md).

## Стартиране с Docker Compose

```bash
cd platform
cp .env.example .env
# 1) задай POSTGRES_PASSWORD в .env
# 2) генерирай тайни и ги сложи в .env (SECRETS_MASTER_KEY, по желание MCP_TOKEN):
docker compose run --rm --no-deps api python -m app.cli gen-keys
# 3) по желание: TYPESAFE_API_KEY в .env (без него няма сигнали, но цените и симулацията вървят)
docker compose up -d --build
docker compose exec api python -m app.cli create-user moeto-ime   # пита за парола (≥ 12 знака)
```

Отвори http://127.0.0.1:3000. Портовете са вързани само към `127.0.0.1`, така че таблото не е
публично. Ако го пуснеш зад HTTPS, задай `COOKIE_SECURE=true`.

Полезни команди:

```bash
docker compose logs -f engine          # какво прави двигателят
docker compose restart engine          # рестарт; чакащите поръчки се съгласуват с брокера
docker compose --profile mcp up -d mcp # read-only MCP на 127.0.0.1:8100
```

### Демо без живи данни

За преглед на таблото без интернет и ключове се използват **синтетични** данни. Те винаги са с етикет
„ТЕСТОВИ ДАННИ“ и се зареждат само в отделна, празна база:

```bash
DATABASE_URL=postgresql+psycopg://trader:...@127.0.0.1:5432/trading_demo python -m app.cli seed-demo
```

Двигателят отказва да продължи портфейл от тестови данни с живи цени.

## Bybit: регион и ключ

- `BYBIT_REGION=eu` (по подразбиране) използва `api.bybit.eu`, предназначен за сметки от ЕИП (Bybit EU).
  Глобален акаунт се избира с `BYBIT_REGION=global`.
- Цените идват от публичния поток `stream.bybit.com`, защото за ЕИП няма отделен. Таблото ги
  показва като „Bybit публичен spot поток“, не като цена на изпълнение в Bybit EU.
- Ключ не е нужен за цените и симулацията. Ако искаш таблото да провери сметката (баланси, права):
  1. Bybit EU → API → нов ключ от тип **API Transaction**.
  2. Права: **само Spot търговия**. **Без Wallet** (теглене, прехвърляне). По възможност с IP ограничение.
  3. В таблото: „API ключове на борсата“ → запази (криптира се със `SECRETS_MASTER_KEY`) →
     „Провери правата“. Ключ с право на теглене или прехвърляне се отказва.
- Обща бележка: документацията на V5 още казва, че API-то на EU сайта е само за свързани приложения.
  Обявата на Bybit EU от 02.09.2026 въвежда лични ключове. Ако Bybit EU не позволи личен ключ,
  проверката ще покаже грешката.

## Колко струва една сделка (честно)

| Разход | Стойност по подразбиране |
|---|---|
| Такса taker в Bybit EU (без VIP) | 0,25% на страна, т.е. 0,50% за покупка и продажба |
| Приплъзване | 0,05% на страна (допускане) |
| Спред | около 0,01% при BTC/EUR (зависи от момента) |
| **Общо за отиване и връщане** | **около 0,6%** |

Затова целта X е „цената след 30 мин да е поне около 0,7% над сегашната“, т.е. разходите плюс 0,1% марж.
Такова движение за 30 минути е **рядко**. Повечето оценки ще са „задръж“. Разходите доминират при кратък
хоризонт; това е очаквано, а не грешка.

Още допускания на симулацията (показани и в таблото):
- покупка по ask плюс приплъзване, продажба по bid минус приплъзване;
- частични изпълнения до 50% от видимото количество;
- минимален размер и стъпка от Bybit, когато са достъпни;
- защитните изходи са пазарни поръчки и цената не е гарантирана.

## Контроли

- **„Спри новите поръчки“** спира новите покупки (и автоматичните изходи, ако `PAUSE_BLOCKS_EXITS=true`).
  **Не продава нищо.**
- **„Отмени чакащите поръчки“** отменя отворените поръчки при брокера.
- **„Продай позицията“** продава целия свободен BTC, включително началния, с изрично потвърждение.
  Двигателят пак проверява свежестта на котировката и спреда.
- **Смяна на борса** сменя източника на цени и двигателят се рестартира сам. **Не прехвърля средства.**

## Тестове

```bash
cd platform/backend && TEST_DATABASE_URL=postgresql+psycopg://...trading_test pytest -q && ruff check .
cd ../frontend && npx tsc --noEmit && npm run build
cd .. && E2E_PYTHON=python PW_CHROMIUM_PATH=/path/to/chromium ./scripts/e2e.sh   # браузърна проба
```

`scripts/e2e.sh` изтрива и пълни базата за проба. Затова отказва база, чието име не съдържа `e2e` или `test`.

### 24-часов PAPER тест

```bash
./scripts/soak_24h.sh             # docker compose exec api python -m app.cli soak --hours 24
```

Записва проба всяка минута и отчет `reports/soak-*.md`. Ако тестът бъде прекъснат, отчетът го казва
изрично. **Този тест не е пускан** в средата, където е писан кодът, защото тя няма достъп до борсите.

### Исторически тест без поглед напред

```bash
docker compose exec api python -m app.cli evaluate --tune-fraction 0.6
```

Как работи:
- Използва записаните сигнали; всеки е направен само с данни до своя момент, а резултатът е записан
  30 минути по-късно.
- Прагът се избира само по по-ранния период и се отчита по по-късния, заедно с варианта „без търговия“.
- Под около 100 сигнала резултатът е шум и отчетът го пише.

## MCP (по избор, само четене)

```bash
docker compose --profile mcp up -d mcp     # изисква MCP_TOKEN (≥ 32 знака) в .env
```

Инструментите са `portfolio`, `bot_status`, `recent_signals`, `trade_history` и `simulation_results`.
Нито един не може да търгува. Свързване от Claude Code на същата машина:

```bash
claude mcp add --transport http trading-readonly http://127.0.0.1:8100/mcp \
  --header "Authorization: Bearer <MCP_TOKEN>"
```

Уеб чат приложенията (например ChatGPT) изискват публичен HTTPS адрес. Такъв **не е създаден**, защото
публично разгръщане става само с твое разрешение. Този чат **не е свързан** с платформата.

## Сигурност

- Ключовете за борсите са криптирани с Fernet в базата.
  - Не се връщат към браузъра.
  - Не се пишат в логовете и одита.
  - Не се пращат към Jev.
- Новините се подават на Jev като недоверени данни, никога като инструкции.
- Сесиите са HttpOnly бисквитки със SameSite=Strict и CSRF заглавка; паролите са с argon2id.
- Няма недокументирани адреси и няма автоматичен вход с парола (Robinhood EU е „недостъпен“).

## Какво остава да направиш

1. **`TYPESAFE_API_KEY`**: без него няма сигнали от Jev.
2. **Bybit EU ключ** (по желание, само за проверка на сметката): API Transaction, само Spot, без Wallet права.
3. **24-часовият тест**: `docker compose up -d`, после `./scripts/soak_24h.sh`.
4. **Решение за LIVE**: изисква изрично разрешение, малък тест с реален ключ и промяна в кода, която
   отключва адаптера. Нищо от това не е направено.
5. По желание: `INFRA_COST_EUR_PER_MONTH` и `NEWS_COST_EUR_PER_MONTH`, ако плащаш сървър или новини.
